Projeto Prático: Roteador de 3 Vias

Moss

Um agente sem memória decide bem uma vez e esquece a decisão no turno seguinte. Vamos construir isso com contexto persistente desde o início.

Passo 1: O Classificador (LLM + Temperature 0.0)

1

Configure o modelo pra ser previsível

Roteamento precisa ser determinístico: nada de o mesmo input gerar rotas diferentes em execuções diferentes:

from langchain_google_genai import ChatGoogleGenerativeAI

roteador = ChatGoogleGenerativeAI(
    model="gemini-2.5-flash",
    temperature=0.0
)

Passo 2: O Contrato (System Prompt)

2

Defina escopo, formato e limites: tudo junto

SYSTEM_PROMPT = """
Você é um classificador de intenção. Sua única tarefa é ler a
mensagem do usuário e responder EXATAMENTE no formato:
ROUTE=financeiro | ROUTE=agenda | ROUTE=faq

Nunca escreva nada além da rota. Se a mensagem não for sobre
finanças, agenda ou dúvidas de uso do sistema, responda ROUTE=faq.
"""

Repare: persona (classificador), formato de saída (ROUTE=X) e o caso de fallback (faq) estão todos definidos numa única string: nada fica implícito.

Passo 3: O Segurança (Guardrail)

3

Valide a saída antes de confiar nela

import re

def validar_rota(resposta: str) -> str:
    match = re.fullmatch(r"ROUTE=(financeiro|agenda|faq)", resposta.strip())
    if not match:
        return "ROUTE=faq"  # fallback seguro se o formato vier errado
    return resposta.strip()

Um guardrail não confia cegamente na saída do modelo: mesmo com temperature 0.0 e um bom System Prompt, vale validar o formato com uma regra fixa antes de rotear de verdade.

Passo 4: O Arquivista (Memória com thread_id)

4

Dê contexto entre turnos

from langgraph.checkpoint.memory import MemorySaver

memoria = MemorySaver()
config = {"configurable": {"thread_id": session_id}}

resposta = grafo.invoke({"mensagem": entrada_usuario}, config=config)

Gerar o thread_id uma vez por sessão (não a cada mensagem!) é o que permite ao agente lembrar que "foi 5 reais" se refere à pergunta anterior sobre um gasto.

O fluxo completo, de novo

Mensagem do usuário → Classificador decide a rota (temp 0.0) → Segurança valida o formato → a rota valida segue pro agente especialista certo, com o thread_id garantindo que ele lembra da conversa. Cada seta é uma fronteira que a camada seguinte não deveria atravessar.

Checklist de conclusão

Se todos esses pontos fazem sentido, o projeto está de pé:

  • O roteador nunca responde nada além de ROUTE=X.
  • A temperatura do roteador é 0.0, não a mesma usada pra geração de texto.
  • Existe uma validação de formato antes de confiar na saída do modelo.
  • O thread_id é gerado uma vez por sessão, não recriado a cada mensagem.
